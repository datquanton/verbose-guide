# Portfolio consultant (`/danh-muc/`)

An interactive page: the investor enters positions and views; the page returns sizing, concentration,
entry/exit and the evidence for and against from the site's reports. No server, no account; input stays in the browser.

| File | What | Refresh when |
|---|---|---|
| `research.js` | Evidence base: every claim is copied from a published report and names its source | a report is published or revised |
| `market.js` | Volatility, trend, beta, correlation, valuation for 77 tickers. Generated by `build_market.py` | every 1–2 weeks (the page warns after 14 days) |
| `company.js` | Company fact base: 11 quarters of revenue, profit, returns, margins, debt, bank and broker ratios, valuation history for 77 tickers. Generated by `build_company.py` | after each results season, or when a company files late |
| `facts.js` | Turns `company.js` into the fact card and data-derived evidence for a ticker | a rule or wording changes |
| `flow.js` | Foreign net buying, active buy/sell imbalance, 6- and 12-month price change per ticker. Generated by `build_flow.py` | every 1–2 weeks, with prices |
| `factors.js` | Factor scores (value, growth, quality, momentum, low risk, flow) as percentile ranks; sector medians; portfolio exposure | a factor definition changes |
| `backtest.js` | Results of the factor backtest shown on the page. Generated by `backtest_factors.py` | when history is extended; the reading text in `i18n.js` (`bt.read`) quotes figures and must be updated with it |
| `engine.js` | Sizing and risk rules. Pure functions, runs in Node for testing | a rule changes |
| `i18n.js` | All interface text, Vietnamese and English | wording changes |
| `intake.js` | Reads a pasted list or a broker screenshot into ticker and weight rows; the parser runs in Node for testing | a broker layout is misread |
| `vendor/tesseract/` | Self-hosted text recognition, loaded only when a screenshot is chosen | upgrading the library |
| `app.js`, `app.css` | Interview, form and rendering | — |
| `OVERNIGHT.md` | Brief for unattended maintenance runs, with a run log | after each run |

Refreshing prices: pull ~260 adjusted daily closes per ticker (plus `VNINDEX`) from FiinQuantX, save the JSON responses, then
`python3 build_market.py prices*.json > market.js`. Valuation and liquidity figures are the `SNAP` table inside the script; update it and `SNAP_DATE` from the same day's snapshot.

Refreshing company facts: call FiinQuantX `FundamentalAnalysis.get_ratios` and `FundamentalAnalysis.get_financial_statement` (statement `incomestatement`) for every ticker in `market.js`, years covering the last 11 quarters, quarters 1–4, type `consolidated`; save both JSON responses, then
`python3 build_company.py ratios.json income.json > company.js`. The provider's ratios are trailing twelve months (checked against the raw statements).

Refreshing flow: pull ~260 daily sessions with fields `close, value, fn, bu, sd` for every ticker in `market.js` plus `VNINDEX`, save the JSON responses, then `python3 build_flow.py flows*.json > flow.js`. This feed skips some sessions, so do not feed these files to `build_market.py`.

Re-running the backtest: build `prices.json` (`{ticker: {date: adjusted close}}`, daily from mid-2018, with `VNINDEX`; the provider caps a call at 50,000 rows, so pull about 20 tickers at a time) and `fund.json` (`{ticker: [{y, q, rev, np, roe}]}` from the same two FundamentalAnalysis calls, years from 2017), then `python3 backtest_factors.py prices.json fund.json market.js > backtest.js`. Method and known biases are in the script's header.

Not generated by the site generator: the homepage card and nav link were added by hand to `/index.html` and `/en/index.html`.
